# Apple platforms: iOS and Apple TV

This branch (`feat/ios-apple-tv`) adds the two Apple targets and the build path
that keeps them at parity with the Android phone and Google TV apps.

Parity means the same server, the same guide/DVR data, the same streams and the
same version number. It does **not** mean the same UI code on both Apple
platforms, because tvOS has no public WebView (see below).

## The tvOS constraint

Apple does not ship `WebKit.framework` for tvOS. `UIWebView` is marked
`__TVOS_PROHIBITED`, and the radar asking for `WKWebView` on tvOS
([22738023](https://github.com/lionheart/openradar-mirror/issues/6085)) is still
open. The wrappers that do render web content on Apple TV use private APIs and
are not App Store distributable.

That rules out a Capacitor shell, a WKWebView shell, and reusing the Angular UI
on Apple TV. The Apple TV client must be native. It can still reach full parity
because all of the app logic lives behind the Tuner Daemon REST API; the native
client is another API consumer, not another copy of the server logic.

## Architecture

| Platform | Shell | UI | Input | Project |
| :--- | :--- | :--- | :--- | :--- |
| Android phone | Capacitor Android (`mobile`) | Angular bundle | touch | `client/android` |
| Google TV | Capacitor Android (`tv`) | Angular bundle | D-pad | `client/android` |
| iPhone / iPad | Capacitor iOS | Angular bundle | touch | `client/ios` |
| Apple TV | Native tvOS (SwiftUI) | Native SwiftUI + AVPlayer | Siri Remote | `client/tvos` |

### iOS

`client/ios` is the standard Capacitor 8 project, generated with
`npx cap add ios` and using Swift Package Manager (the Capacitor 8 default).
`client/capacitor.config.ts` supplies the app id and web directory.

`scripts/build-mobile-web.sh` builds the same Angular bundle as Android and
fixes the SPA entry point: Angular's static build emits a redirect document for
the empty route, which would leave the Capacitor WebView on "Redirecting to
/watch". The script copies the prerendered Watch shell over the root
`index.html`, and Android, iOS and the web harness all use it.

The only iOS-specific native change is the ATS exception in
`client/ios/App/App/Info.plist`. IPTV servers frequently serve plain HTTP on the
LAN, and Android already enables cleartext.

### Apple TV

`client/tvos` is a native tvOS app generated by
[XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. The first
slice is in place and playable:

1. **Server setup** — server address persisted in `UserDefaults`, with the same
   default server as the web and Android clients.
2. **Channel grid** — `/api/guide` (public), current programme and channel
   number, logos resolved against the configured server.
3. **Player** — `AVPlayerViewController` with the HLS URL from
   `/api/channel/:id/stream`, native tvOS transport controls, a 10-second
   keep-alive ping, and the same 12-second startup watchdog as the web player.
   Menu returns to the grid.

The next slices are the programme guide, DVR, and settings (favorites, hidden
channels, playback preferences). The API is already there; this is UI work.

The native UI owns tvOS focus, so the Siri Remote drives SwiftUI's focus engine
instead of synthetic keyboard events. That is the one intentional behavioural
difference from Google TV: both are D-pad, but only one goes through the DOM.

[XcodeGen]: https://github.com/yonaskolb/XcodeGen

## Building locally

Requires macOS with Xcode 16 or newer. tvOS also needs XcodeGen
(`brew install xcodegen`). The simulator builds are unsigned, so no Apple
Developer account is required.

```bash
npm run build:ios     # iOS simulator app
npm run build:tvos    # Apple TV simulator app
npm run build:apple   # both
```

Outputs land in `scratch/ios-derived/Build/Products` and
`scratch/tvos-derived/Build/Products`.

To open the projects:

```bash
open client/ios/App/App.xcodeproj
cd client/tvos && xcodegen generate && open TunerDaemonTV.xcodeproj
```

The iOS app starts on the server picker; the default server is the same
`https://teevee.christopherrutherford.net` used by the Android build, and
Settings → Server changes it.

## CI

`.github/workflows/apple.yml` runs on macOS and produces unsigned simulator
`.app` bundles as workflow artifacts:

- `ios-simulator/tuner-daemon-ios-simulator.zip`
- `tvos-simulator/tuner-daemon-tvos-simulator.zip`

The workflow triggers on changes to `client/ios`, `client/tvos`, the mobile
build scripts, the Capacitor config and the client source. It does not run on
Linux, because Xcode is required.

## Signing and distribution

Unsigned simulator builds prove the code compiles; they are not installable
packages. Producing `.ipa`/`.app` packages for devices or TestFlight/App Store
requires an Apple Developer Program membership and these repository secrets (or
local equivalents):

| Secret | Used for |
| :--- | :--- |
| `APPLE_TEAM_ID` | `DEVELOPMENT_TEAM` |
| `APPLE_CERTIFICATE_BASE64` | distribution certificate (.p12, base64) |
| `APPLE_CERTIFICATE_PASSWORD` | certificate password |
| `APPLE_PROVISIONING_PROFILE_BASE64` | provisioning profile (.mobileprovision) |
| `APPLE_PROVISIONING_PROFILE_SPECIFIER` | profile name |
| `APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` | optional `altool` upload |

The manual path:

1. Open the Xcode project, select the App target, choose the team, and confirm
   the bundle identifier (`net.christopherrutherford.tunerdaemon` for iOS and
   `net.christopherrutherford.tunerdaemon.tv` for tvOS).
2. Product → Archive.
3. Distribute App → App Store Connect / Ad Hoc / Development.

For iOS, `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` are set by
`npm run version:set`; the tvOS equivalents live in `client/tvos/project.yml`.
The same command updates both, and `npm run version:check` refuses a release
whose Apple build number disagrees with the Android APK and the tag.

> tvOS icons are a single-layer `AppIcon.brandassets` stack generated from
> `client/src/assets/tuner-daemon-512.png` at 400×240 / 800×480 and 1280×768.
> Replace the flat layer with a designed layered stack before App Store
> submission; the structure is already correct.

The Android columns are the reference. Apple columns move to "verified" only
after a run on real hardware.

| :--- | :---: | :---: | :---: | :---: |
| Shared Angular bundle | ✅ | ✅ | ✅ | — native |
| Server URL + persisted settings | ✅ | ✅ | ✅ | ✅ |
| Channel list + current programme | ✅ | ✅ | ✅ | ✅ |
| Full guide, recording, DVR | ✅ | ✅ | ✅ | ⏳ native UI |
| HLS live playback | ✅ | ✅ | ✅ | ✅ AVPlayer |
| Touch / pointer input | ✅ | — | ✅ | — |
| D-pad / remote focus | — | ✅ | — | ✅ SwiftUI focus |
| Back / menu leaves playback | ✅ | ✅ | ✅ | ✅ |
| Play/pause from remote | — | ✅ | — | ✅ AVPlayerViewController |

### Known gaps to close next

1. **Build the remaining native tvOS screens.** The server picker, channel grid
   and player are in place. The full programme guide, DVR and settings are the
   main body of work left on the branch; the API is already there.
2. **Signed packages and release assets.** Add a credentialed macOS job that
   archives/exports and attaches the `.ipa` and tvOS package to the GitHub
   Release. The workflow must degrade cleanly when secrets are absent.
3. **Hardware verification.** Siri Remote focus, hold-to-repeat on the guide,
   menu-to-exit, and AVPlayer error recovery need a real Apple TV run.
4. **Layered tvOS icon art.** The `App Icon & Top Shelf Image.brandassets`
   structure is in place, but the Front layer is a flat placeholder. Replace it
   with designed parallax layers (and add Top Shelf images) for submission.
5. **PiP / background audio.** PiP is available to the native tvOS player via
   AVKit; background audio still needs a product decision for every platform.
6. **Deep links / universal links.** Not present on Android today; add to both
   platforms together if needed.
