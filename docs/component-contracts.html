Component contracts

The rules a screen must follow to look and behave like Tuner Daemon. This page is the reference for review: if a component is not described here, it is a one-off and needs a reason.

Minimum target is 44 × 44 px on touch layouts and 32 × 32 px for icon-only controls on desktop. All icon-only buttons require aria-label or title.

Fields and validation

Enter a number between 1 and 14.

Every input has a visible label. Errors point at the field, set aria-invalid, and describe the fix. A save that is rejected keeps the user's values and names each bad field — it never silently discards input.

Surfaces and states

Card

One job per card. A heading, optional lead, content. --bg-surface plus --border-subtle. No nested cards.

Data table

Header stays visible; rows are 44–48 px. Below 768 px the table becomes labelled cards, and every row action stays reachable.

Empty state

Name the next action, not the absence. A first run opens the playlist picker instead of an empty health table.

Error state. Say what failed, keep the retry in place, and log the technical detail to the console rather than the page.
Empty state: “No playlist selected yet. Add one below or pick a free channel preset.”

Watch guide (mobile)

The timeline and programme rows share one horizontal scroll surface. Below 860 px the right edge fades and a “Swipe for more” hint appears; both disappear once the grid reaches its end. The hint is decorative (aria-hidden) and never blocks a programme cell.

Scroll containers own overscroll: overscroll-behavior-x: contain. A sideways swipe in the guide must never navigate the browser history.

Accessibility contract

  • axe-core serious/critical findings: zero on every admin screen, Watch and mobile Watch.
  • Focus is always visible: 2 px outline with 2 px offset, never removed without a replacement.
  • Colour is never the only signal. Status badges pair colour with text.
  • Motion respects prefers-reduced-motion for anything that loops or travels.
  • Lighthouse accessibility is a floor of 95; the axe gate is the stricter per-screen check.

Change rule

A new visual variant is a design-system change, not a local fix. Add the token or component here first, then use it. One-off hex values, sub-12px labels, white-on-semantic-fill buttons and shadowed cards inside cards are review failures.
